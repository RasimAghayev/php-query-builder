## Design limitation, not a bug (documented, not fixed)

- **No SQL parameterization.** Every value passed to `where()`/`whereIn()`/`whereBetween()`/etc. is turned into a literal via `escapeValue()` (wraps strings in single quotes, casts everything else) and concatenated directly into the returned SQL string — there is no placeholder/binding mechanism, and `escapeValue()` does not escape embedded quote characters. This repo never executes the SQL it builds (no PDO/mysqli anywhere in `src/`), so there's no injection vector *within this repo's own code*, but any consumer that executes `toSql()`'s output against a real database using unsanitized user input would be SQL-injectable. Fixing this (parameter binding, proper escaping) would be a breaking API change to every method signature and `toSql()`'s return contract — out of scope for a bug-fix/test pass; flagged for `docs/IMPROVEMENT_ROADMAP.md` instead.

## Not treated as debt

- The non-standard `.inc` extension for PHP classes (`QueryBuilder.inc`, the four interface files) is unusual but functionally harmless — Composer's autoloader works from the paths declared in `composer.json`, not the extension. Cosmetic/stylistic, not a defect.
- `src/index.php`'s demo script requiring `vendor/autoload.php` and being runnable via `php -S localhost:3000 index.php` (per the README) is a deliberate, working demo entry point, not a bug.
